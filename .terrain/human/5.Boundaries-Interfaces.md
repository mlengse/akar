# System Boundary Interfaces

This document covers all external-facing interfaces of Akar — the "front doors" through which users, applications, and other systems interact with the database engine. Understanding these interfaces is essential for anyone building on top of Akar or integrating it into a larger system.

---

## 1. Rust Library API (akar-main)

The primary and most complete interface. Designed for embedding Akar directly into Rust applications.

### Database

```rust
use akar_main::{Database, Connection, SystemConfig};

let config = SystemConfig::default();
let db = Arc::new(Database::new("/path/to/db", config)?);
let conn = Connection::new(&db);
```

| Method | Description | Notes |
|--------|-------------|-------|
| `Database::new(path, config)` | Create or open a database | Path can be `:memory:` for in-memory mode |
| `Database::connect_tcp(addr)` | Connect to remote TCP server | Returns `RemoteDatabase` |
| `Connection::query(cypher)` | Execute a Cypher query | Returns `Result<QueryResult, String>` |
| `Connection::prepare(cypher)` | Prepare a parameterized statement | Returns `PreparedStatement` |
| `Connection::execute(stmt, params)` | Execute prepared statement | Named `$param` support |

### SystemConfig

| Parameter | Type | Default | Meaning |
|-----------|------|---------|---------|
| `buffer_pool_size` | u64 | 256MB | How much memory the buffer manager can use for caching pages — larger values mean more data stays in memory |
| `max_num_threads` | u64 | num_cpus | Maximum parallelism for query execution — set this to match your CPU core count |
| `enable_compression` | bool | true | Column-level compression (constant, boolean, string dictionary) — reduces I/O at slight CPU cost |
| `read_only` | bool | false | Open database in read-only mode — useful for read replicas |
| `concurrent_writes` | bool | false | Enable OCC-based concurrent multi-writer — required for multi-agent architectures |
| `checkpoint_threshold` | u64 | 4096 | WAL size before auto-checkpoint — lower values mean more frequent checkpoints (less recovery time, more I/O) |
| `spill_threshold` | u64 | 2^31 | NodeGroup size before spilling to disk — controls memory usage for large inserts |

## 2. Interactive CLI (akar-cli)

A rustyline-based REPL for interactive Cypher exploration. Useful for schema exploration, ad-hoc queries, and debugging.

### Usage

```bash
# Interactive mode
cargo run --bin akar-cli -- /path/to/db

# Script mode (piped input)
echo "MATCH (n) RETURN count(n)" | cargo run --bin akar-cli -- /path/to/db

# In-memory database
cargo run --bin akar-cli
```

### REPL Features

| Feature | Description | How to Use |
|---------|-------------|------------|
| Multi-line input | Continuation prompt `..>` until `;` | Type query across multiple lines |
| Tab completion | 30+ keywords + table names | Press Tab |
| Output modes | 8 formatters | `.mode table\|csv\|json\|line\|column\|box\|html\|latex` |
| Import CSV | Load CSV into table | `.import data.csv tablename` |
| Export results | Save query results to file | `.export output.csv "MATCH (n) RETURN n"` |
| Schema info | Show tables and schema | `.tables` / `.schema` |
| History | Persistent history | Platform data dir (`akra/history.txt`) |
| Confidential scrub | CALL statements with secrets excluded from history | Automatic |

## 3. C FFI (akar-c)

`extern "C"` API for language bindings (Python, Go, Java, etc.). All functions are wrapped in a `catch()` boundary to prevent panics from crossing the FFI boundary (which would be undefined behavior).

### Exported Functions

| Function | Signature | Description |
|----------|-----------|-------------|
| `akar_default_system_config` | `() -> akar_system_config` | Get default configuration |
| `akar_database_init` | `(path, config, *mut db) -> akar_state` | Create/open database |
| `akar_database_destroy` | `(*mut db)` | Destroy database (idempotent) |
| `akar_connection_init` | `(*mut db, *mut conn)` | Create connection |
| `akar_connection_destroy` | `(*mut conn)` | Destroy connection |
| `akar_connection_query` | `(conn, query, *mut result, *mut error) -> akar_state` | Execute query; error detail heap-allocated |
| `akar_error_message_free` | `(*mut error)` | Free error string |
| `akar_query_result_destroy` | `(*mut result)` | Free result (Rust Box, never C free) |

### Error Handling

Errors are returned as `akar_state::AkarError` (value 1) with an optional heap-allocated C string error message. Always call `akar_error_message_free()` after checking for errors.

## 4. WebAssembly Bindings (akar-wasm)

wasm-bindgen classes for browser execution. In-memory only on wasm32 (no filesystem access).

### Exported Classes

| Class | Methods | Description |
|-------|---------|-------------|
| `AkarDatabase` | `new(db_path)` | Create database (in-memory only on wasm32) |
| `AkarConnection` | `new(db)`, `query(str)`, `prepare(str)`, `execute(prepared, params)` | Execute queries |
| `AkarPreparedStatement` | Wraps native PreparedStatement | Parameterized queries |
| `QueryResult` | `is_success()`, `get_next()`, `get_column_names()`, `has_next()` | Iterate results |

### JS -> Value Coercion

| JS Type | Akar Type | Notes |
|---------|-----------|-------|
| `null` | `Value::Null` | |
| `boolean` | `Value::Bool` | |
| `number` (integral) | `Value::Int64` | If the number is an integer |
| `number` (fractional) | `Value::Double` | Otherwise |
| `string` | `Value::String` | |

## 5. TCP Server (akar-server)

Embedded TCP server for multi-process access. One owner process holds the file lock; N clients query over TCP.

### Protocol

- **Framing:** `[u32 LE payload_len][JSON bytes]`
- **Max frame size:** 128 MiB
- **Auth:** Optional bearer token (checked on first frame)
- **Timeouts:** Read 250ms / Write 10s

### Operations

| Operation | Description | Request Fields |
|-----------|-------------|---------------|
| `query` | Execute Cypher query | `query`, `client_name`, `params` (optional) |
| `ping` | Health check | — |
| `flush` | CHECKPOINT | — |
| `stats` | Server statistics | — |
| `export` | EXPORT DATABASE | `path` |
| `shutdown` | Graceful shutdown | — |
| `dream_control` | Dream engine control | `action` (status/pause/resume/run) |

### Server Configuration

| Parameter | Default | Meaning |
|-----------|---------|---------|
| `addr` | `127.0.0.1:0` | Bind address (0 = ephemeral port) |
| `auth_token` | None | Bearer token for authentication |
| `idle_timeout` | None | Disconnect idle clients after this duration |

## 6. Python Bindings (akar-python)

Drop-in KuzuDB replacement via PyO3. Single-line change: `import kuzu` -> `import akar`.

### API Surface

| Class | Methods | Description |
|-------|---------|-------------|
| `Database(path)` | `close()`, `__repr__` | Create/open database |
| `Connection` | `query(cypher)`, `execute(cypher, params)` | Execute queries |
| `QueryResult` | `has_next()`, `get_next()`, `get_column_names()`, `rows_as_dict()`, `get_all()` | Iterate results |

### Cypher Translation

The Python bindings include a translation layer that converts Kuzu Cypher syntax to Akar SQL:
- `FLOAT[n]` -> array type syntax
- `IF NOT EXISTS` handling
- CALL vector index syntax
- Multi-statement `INSTALL; LOAD` sequences
- `ALTER ... DEFAULT` column defaults

## 7. Extension API (akar-extension)

The plugin SPI for adding new capabilities to Akar.

### Extension Trait

```rust
trait Extension: Send + Sync {
    fn name(&self) -> &'static str;
    fn load(&self, context: &ExtensionContext) -> Result<(), String>;
}
```

### ExtensionContext

| Method | Description |
|--------|-------------|
| `register_scalar_function(name, func)` | Register a new scalar function |
| `register_aggregate_function(name, func)` | Register a new aggregate function |
| `register_table_function(name, func)` | Register a new table function |
| `register_file_system(scheme, fs)` | Register a virtual filesystem handler |
| `catalog()` | Access the system Catalog |
| `function_registry()` | Access the FunctionRegistry |

### Adding a New Extension

1. Create a new crate in `akar-core/`
2. Implement the `Extension` trait
3. In `load()`, register your functions via `ExtensionContext`
4. Add a feature flag to `akar-main/Cargo.toml`
5. Register the extension in `database.rs:register_builtin_extensions()`

## 8. Configuration

### SystemConfig (Runtime)

All configuration is passed via `SystemConfig` at database creation time. There are no configuration files — the database is configured programmatically.

### Cargo Feature Flags (Compile-Time)

Extensions are compiled statically via feature flags:

```toml
[dependencies]
akar-main = { version = "0.2.3", features = [
    "json-extension",
    "fts-extension",
    "vector-extension",
    "algo-extension",
    "httpfs-extension",
    "duckdb-extension",
    "sqlite-extension",
    "postgres-extension",
    "neo4j-extension",
    "llm-extension",
    "delta-extension",
    "iceberg-extension",
    "azure-extension",
    "unity-catalog-extension",
    "ml-extension",
]}
```

## Integration Recommendations

**For AI agent developers:** Use the Rust library API directly. Create a `Database` with `SystemConfig::default()`, create a `Connection`, and execute Cypher queries. Enable `concurrent_writes` if multiple agents share the database.

**For multi-process applications:** Use the TCP server mode. One process owns the database (holds the file lock), and other processes connect via TCP. Enable auth_token for security.

**For browser applications:** Use the WASM bindings. Note that WASM mode is in-memory only — no disk persistence.

**For Python applications:** Use the PyO3 bindings. `pip install akar` and `import akar`. The Cypher translation layer handles Kuzu syntax compatibility.

**For C/C++ applications:** Use the C FFI. All functions are wrapped in `catch()` to prevent panics across the FFI boundary.
